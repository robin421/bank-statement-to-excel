## 1. Git history privacy

Enumerated every reachable object, not just `HEAD`:

```
git rev-list --objects --all | grep '\.pdf$' | grep -c 'corpus/'   →  0
```

All 14 PDF objects in history are `fixtures/pdf/*.pdf`, generated by
`fixtures/generate.mjs` from a seeded PRNG. No renamed or moved real statement
survives: the only `corpus/` paths ever committed are the reports, the manifests, the
diagnostic ground-truth JSON and one directory entry — all text.

Nothing exceeded 1 MB, so there is no hidden blob to catch by size.

## 5. Clean clone verification

Cloned from GitHub into an empty directory. Confirmed absent before installing:
`fixtures/real/`, `corpus/court/`, `.env`, `node_modules/`.

```
npm ci         → exit 0
npm run verify → 136 passed · 22 pages · all internal links resolve
```

The two invariants that were previously coupled remain separated, which is the
specific regression this gate exists to catch:

- **policy invariant** — an excluded fixture must carry a recorded reason; holds everywhere, including here.
- **local condition** — the excluded file exists; meaningful only where the corpus is present.

`tests/real-corpus.spec.ts` reports 5 passed, 0 failed with no corpus.

## 6. CI semantics

`.github/workflows/ci.yml` runs `npm ci` and `npm run verify`, and carries an explicit
comment that `tests/real-corpus.spec.ts` **skips** because the corpus is gitignored, so
a green run "does NOT prove anything about real bank statements". The README repeats
the same claim. Workflow, README and repository policy agree.

The browser smoke suite is deliberately not run in CI: it needs a large Playwright
download, and it is more informative run locally against production.

## 12. Git object health — one finding, benign

`git fsck` reports **0 errors**. Two observations:

**Pack directory is clean.** Only the three legitimate pack files are present. The
`._pack-*.idx` sidecars that previously made `git gc` fail with `non-monotonic index`
have not returned, because the `com.apple.provenance` extended attribute was cleared
from the pack files and macOS only writes an AppleDouble companion for files that carry
xattrs. **No GC was run** — there is nothing to reclaim: `size-pack 428 KiB`, `count 0`
after the purge, and the 7 MiB of loose objects that has accumulated since is normal
for 28 commits and would be packed by the next routine gc.

**Seven `._*` sidecars elsewhere under `.git/objects/`.** Cause confirmed as the same
exFAT AppleDouble behaviour. Each was checked against its counterpart before being
called benign, per the standing rule that these are never removed on sight:

- four are companions to loose object *files* — counterparts present
- three (`._16`, `._6c`, `._bf`) are companions to loose object *directories* — counterparts present
- all seven are reported by git as `garbage found`; none is referenced by a ref
- `git fsck` errors: **0**

They are cosmetic warnings, will recur on this volume for as long as commits are made
here, and were deliberately **not** cleaned, because removing them changes nothing and
this round forbids unnecessary cleanup.

## 14. LICENSE — resolved, as source-available

The audit found no LICENSE file and recorded it as an unresolved owner decision rather
than defaulting to open source. It has since been resolved, in the only direction that
is reversible.

`LICENSE` now states **all rights reserved**, with a plain-language summary of what is
and is not permitted, a no-warranty clause, and a third-party section making clear that
the blanket notice does not claim the npm dependencies, the bank trademarks quoted in
the corpus reports, or the third-party statements those reports cite.

The direction was chosen on irreversibility, not preference:

```
permissive licence, wanted proprietary  ->  anyone who cloned meanwhile keeps those
                                            rights permanently, and they cannot be revoked
proprietary now, wanted permissive later ->  change one file; nothing is lost
```

Those are not symmetric, so the restrictive default was taken. It keeps every option
open, including adopting a permissive licence at any future date.

The README names the position at the top and links to the file, so a reader cannot
mistake public visibility for a grant of rights.
